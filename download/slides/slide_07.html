FleetVision AI | Zeroth Review 07
This slide presents the data architecture of FleetVision AI, covering both the database schema and REST API design. The database schema consists of 22 to 25 normalized tables organized across 10 core modules: user management, vehicle management, driver management, trip management, fuel management, maintenance scheduling, expense tracking, AI predictions, notifications, and audit logging. Tables are grouped into three entity categories: Core Entities encompass Users, Vehicles, and Drivers; Operations covers Trips, Fuel Logs, Maintenance records, and Expenses; and Intelligence includes AI Predictions, Notifications, and Audit Logs. This normalization approach minimizes redundancy while maintaining referential integrity across all modules. We use SQLite as the development database engine with Prisma ORM for type-safe database operations. Prisma provides an intuitive schema definition language, automatic type generation, and efficient query building that significantly reduces boilerplate code compared to raw SQL. The REST API exposes 16 endpoints providing full CRUD operations for all resource types. Authentication is handled through JWT tokens obtained via the POST /api/auth/login endpoint. Standard resource endpoints follow RESTful conventions with GET and POST methods for vehicles, drivers, trips, fuel, maintenance, expenses, and notifications. The dashboard endpoint aggregates data across all modules for the main dashboard view. The AI prediction endpoint uses a dynamic path parameter to access any of the seven AI modules: maintenance, driver, fuel, route, accident risk, vehicle health, and fleet analytics. A seed endpoint enables quick database population for development and testing purposes.
